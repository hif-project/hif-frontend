# Changelog

All notable changes to this project are documented in this file.

## [Unreleased]

- A signal shadowed into a `_sig_var` no longer loses its write-back when a task writes it through an `out`/`inout` argument. `refineToVariables` shadows a signal that is both read as a signal and written as a variable, renaming every reference to the shadow and inserting `sig <= var` after each assignment — but `fillInfoMap` classified references by syntactic context and never consulted the formal's direction, so an actual bound to an `out`/`inout` formal landed in `readUsing`. A `readUsing` reference is renamed and nothing more, and the write-back is inserted only in the loop over assignment targets, where a `ProcedureCall` is not an `Assign`. The rename happened, the write-back did not, and the signal stopped updating: on the reproducing accumulator the regenerated design read `0` for its entire run where its source read `1, 2, 3, 4, 5, 6`. Silent — exit 0, output that compiles under `iverilog` and reparses cleanly. The classification now keys on the formal's direction, and the shadowing path publishes the shadow after the call, carrying a part-select when the actual has one. Which signals get shadowed is deliberately unchanged: a signal written *only* through a task argument is still not shadowed, and its translation is byte-identical. `vhdl2hif` reaches the same code and gains the same fix for a VHDL procedure's `out`/`inout` actual. ([hif-frontend#31](https://github.com/hif-project/hif-frontend/issues/31))

- A SystemVerilog `logic` body declaration carrying `signed` — `logic signed [3:0] s;` — now translates, producing exactly the HIF that `reg signed [3:0] s;` produces. It was a bare `syntax error` and exit 134, while the same declaration written with `reg` worked and `logic [3:0] s;` without `signed` worked, so it was neither qualifier alone but the two together. `logic` is not a lexer keyword, so a body declaration written with it has no declaration rule of its own — the `net_declaration` alternative that would take it is commented out, pointing at `module_instantiation` — and it arrives as a module instantiation whose module identifier is the type name. `signed` had no place in that syntax, so the parse failed before any refinement could run. `module_instantiation` gains an alternative carrying it; a module instantiation cannot be signed, so only the net-declaration reading of that rule is affected, and the grammar's shift/reduce and reduce/reduce conflict counts are unchanged. The scalar form `logic signed s;` also translates now and, like `reg signed s;`, yields an unsigned `Bit` — HIF's `Bit` has no sign, and parity with `reg` is the requirement rather than signedness in the abstract. ([hif-frontend#34](https://github.com/hif-project/hif-frontend/issues/34))

- A parameter written in the shorthand form in an ANSI-style function header — a bare identifier continuing the previous item's direction and type, `function f(input p, q);` — is no longer dropped. The `function_port_list K_COMMA IDENTIFIER` production copied the previous port and renamed it but never pushed it onto the list, so the port was both lost and leaked. `task_port_list`'s equivalent production pushes, having been written for [hif-frontend#25](https://github.com/hif-project/hif-frontend/issues/25), so the function and task spellings of the same shorthand had silently diverged. The visible half was an abort: the function ends up with fewer parameters than the call site passes, no candidate matches and hif-core's declaration lookup asserts, naming neither the function nor the shorthand. The quiet half is that a function nobody calls translated at exit 0 with the wrong signature — measured at 9 `IN` parameters where the source declares 13 — which the issue's severity note had ruled out. ([hif-frontend#27](https://github.com/hif-project/hif-frontend/issues/27))

- `partialFlattening`'s refinement loop now stops when a round collects exactly what the previous round collected. The loop was an unbounded `for (;;)` whose only exit was `collectOnAssigns` ceasing to ask for work, and nothing guaranteed that happened. It does not for a design unit that was instantiated in the source and is not instantiated after elaboration — the losing branch of an `if generate`, for instance: `collectOnAssigns` still collects its view, because it still drives an output port with a continuous assignment, but there is no instance left to flatten, so the round changes nothing and the next one collects the same set. Measured on such a design: identical `views`/`viewRefs` from the second iteration onwards, flat memory, about 430 iterations a second, indefinitely. Repeating a round that changed nothing cannot make progress, so stopping is a termination condition rather than a cut-off, and the work left undone is flattening a design unit nothing instantiates. Reachable only since [hif-core#25](https://github.com/hif-project/hif-core/pull/25) made such a branch removable — before that the abort came first. ([hif-frontend#32](https://github.com/hif-project/hif-frontend/issues/32))

- `verilog2hif` no longer aborts when a net driven by a continuous assignment inside a `for generate` is read from outside the loop. `generateConeFunctions` declares a cone beside the declaration it drives and fills it with copies of that declaration's drivers, which assumes every driver is valid in the declaration's scope; a driver inside a `for generate` is not, so the copy carried references to the genvar and — since [hif-frontend#23](https://github.com/hif-project/hif-frontend/issues/23) declared it there — to the split signal, neither visible at module scope. The cone cannot move into the loop, because the process reading the net is at module scope and `addConesPCalls` has to emit a call it can resolve, so `for generate` loops are now expanded after `partialFlattening` and before the logic-cone passes. Placement is load-bearing: expanding earlier resolves a parameterized loop bound against the module's default, so a leaf declaring `parameter N = 2` instantiated as `#(.N(4))` elaborates two iterations instead of four, at exit 0. For the same reason expansion is skipped under `-s/--structure`, which disables the specialization it depends on, and skipped for any loop whose index does not advance by exactly one, because expansion substitutes the iteration ordinal rather than the genvar's value ([hif-core#24](https://github.com/hif-project/hif-core/issues/24)) — those keep the abort they already have, which is preferable to a silently different design. `IfGenerate` is deliberately untouched. Of the 123 checked-in Verilog designs across this repository and hif-regression that both the pre-change and post-change binaries translate, 121 regenerate byte-identically; one is the expanded fixture above, and one (`param_clog2`) is the pre-existing attribution nondeterminism filed as [hif-frontend#40](https://github.com/hif-project/hif-frontend/issues/40), which the unchanged binary also exhibits on its own. Two more designs go from abort to exit 0, which is the fix. ([hif-frontend#30](https://github.com/hif-project/hif-frontend/issues/30))

- `splitLogicConesLoops` now attributes the write-back assignment it synthesizes for a part-select continuous assign to the statement being split. `assign y[7:4] = a[3:0]` becomes a split signal, the original assignment retargeted to it, and a new write-back `y[7:4] = y_partial0_0`; the retargeted original kept its own code info and the write-back was created with none, so every consumer reading a statement's position off the `Assign` saw nothing for it. Two part-select assignments to one signal therefore produced two genuinely different `muffin` fault locations whose records were identical in every field but `id` — `"source": ""`, `"line": 0` — so neither could be selected by attribute, and hif-core's own diagnostics printed "No source file info available" for the node. Regenerated Verilog is byte-identical: no backend reads `CodeInfo`. The split declaration is deliberately left unattributed, because a later refinement rebuilds signals as variables carrying only name, type and value and would discard it ([hif-frontend#37](https://github.com/hif-project/hif-frontend/issues/37)). ([hif-muffin#24](https://github.com/hif-project/hif-muffin/issues/24))

- The empty `Wait` that `_fixProcessesWithWait` appends to a suspending process now carries `PROPERTY_PROCESS_LOOP_TAIL`. That node is not a statement the source wrote: it records that the process loops back round and reapplies its static sensitivity, which is what the SystemC lowering emits at the tail of its `while (true)`. Every field on it is null, which made it identical to the node `vhdl2hif` produces for VHDL's `wait;` — and that means the opposite, suspend permanently. A backend reading the tree therefore had no way to tell them apart and necessarily got one of the two wrong: `hif2verilog` regenerated a VHDL process ending in `wait;` as a zero-delay `always begin ... end` ([hif-backend#46](https://github.com/hif-project/hif-backend/issues/46)). Naming the node is additive and changes nothing on its own — no existing consumer reads the property, and the node is otherwise unchanged — so `hif2sc` and the core manipulations that treat it as a suspension point are unaffected. (hif-backend#46)

## [1.2.0] - 2026-08-16

- Fixed `verilog2hif` aborting with hif-core's "Declaration not found" on a continuous assignment to an output port whose right-hand side refers to a declaration in the module body — so the design could not be translated at all. An assignment with a constant-looking right-hand side was folded into the target's declaration, and for an output port that declaration lives on the `Entity`, which cannot see `Contents` declarations; the reference was left with nothing to resolve to. Folding is now restricted to values that stay resolvable where they are moved. Reported for a user-defined `function` (#14), but a plain `localparam` failed identically — it was never about functions. Literals, module parameters and system functions were always reachable from the `Entity` and still fold as before. (#14)

## [1.1.0] - 2026-08-13

- Implemented the `~&` (reduction-NAND) operator.
- Fixed `splitLogicConesLoops` to pass explicit `TerminalPrefixOptions` (`recurseIntoMembers`/`recurseIntoSlices` = true) into `getTerminalPrefix`, fixing a declaration-resolution assert on constructs like `gray2bin`/`muxhot`/`shiftreg` that assign to different bit-selects of the same signal.
- Added an end-to-end regression for `$clog2` used in a port range, pairing hif-core's registration fix.
- Migrated the project to the `hif-project` GitHub organization; updated internal references accordingly.
- Replaced the README's ecosystem-navigation list with a link to the organization profile.

## [1.0.0] - 2026-08-12

Initial coordinated release of the HIF toolchain baseline (hif-core, hif-frontend, hif-backend, hif-muffin, all tagged v1.0.0).

- Fixed a heap corruption crash in `verilog2hif` on escaped Verilog identifiers.
- Added support for the 8 basic Verilog gate primitives (`and`/`nand`/`or`/`nor`/`xor`/`xnor`/`buf`/`not`).
- Fixed CI to actually build its `hif-core` dependency (previously failed at the configure step on every run) and consolidated it to a single Linux workflow.
